TEAM PROJECT · ON-DEVICE EDGE AI

Connecting the vehicle-counting pipeline and investigating duplicate counts in Smart Highway ITS

We tallied the traffic volume by vehicle type using the vehicle detection results of APACHE6 NPU and ByteTrack. During the implementation process, we discovered a phenomenon in which Track IDs were disconnected due to classification changes, and analyzed the code structure to organize post-processing supplements and improvement directions.

01

Issues found during implementation

Vehicles of the same model from a distance car and truck at different distances. In the structure of creating a Tracker instance for each vehicle type, the tracking status was not continued when the classification changed, so a new Track ID could be assigned.

02

Impact

Although there is actually only one vehicle, there is a possibility of double counting because the counters judge different IDs as new vehicles. We also identified the problem that if the road area is not differentiated, even vehicles in the opposite lane are included in the target traffic volume.

03

Applied Mitigation

The bottom center point of the bounding box was compared with the free-space mask to count only vehicles within the drivable area. A timestamp condition was also connected to avoid repeatedly processing the same results due to the difference between the rendering cycle and the NPU inference cycle.

Delay in counting and non-detection of stopped vehicles

RESULT & LEARNING

Beyond feature implementation: tracing existing code and narrowing the problem scope

We connected vehicle detection results to statistics and applied post-processing to exclude off-road objects. At the same time, we analyzed the impact of model classification and tracker structure on duplicate aggregation, leaving a basis for next improvement.

01

Real-time statistics connection

We have created a flow that can deliver the cumulative number of vehicles and 10-second section statistics to the Wayland screen.

02

Compensation for aggregation targets

Free-space grounding point judgment was used to reduce statistical inflow from oncoming lanes and off-road objects.

03

Structural Limitation

It was determined that the Track ID continuity issue was difficult to completely resolve through post-processing alone and that a change in the Tracker creation unit was necessary.
