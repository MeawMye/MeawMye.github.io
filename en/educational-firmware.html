01

Problem

The examples for each peripheral worked, but as functions increased, initialization and control code was mixed into the application, making reuse and cause tracking difficult. When transmitting long data via USB CDC, communication also stopped around 500 bytes.

02

My Role

We directly implemented the BSP–Driver–Application layer design, USB CDC and UART common interface, USART6 RX DMA, Internal Flash commands and drivers, button mode switching, and demonstration flow.

03

Approach

  1. SeparationSeparate responsibilities between board initialization, device control, and application logic
  2. IntegrationBundles USB CDC and USART6 into a common UART API and applies RX DMA circular buffer
  3. ControlFlash erase·write·read command and sector information configured with driver
  4. TracingIsolate the cause of the stop by checking CDC transmission/reception status and endpoint reactivation conditions
  5. ComparisonContrast HAL implementation with GPIO, EXTI, and UART register operation

ARCHITECTURE

Separate hardware dependencies and application logic

It was structured to reveal the direction of calls and the responsibilities of each layer.

  1. USB CDCCommand/Data
  2. Ring Bufferreceive archive
  3. UART APIcommon interface
  4. ApplicationCommand/Bridge
  5. DriverUART · Flash

UART BRIDGE

USART6 RX DMA-based forwarding

USART6 RX → DMA circular buffer
USB CDC ↔ Application ↔ USART6
PG14 TX · PG9 RX · 115200 bps

Reception is configured with a DMA circular buffer, and transmission is configured with polling. Bridge mode switches with buttons and commands.

INTERNAL FLASH

Sector 11 Test Command

Base address  0x080E0000
Sector        11
Commands      erase / write / read

Sector information and access code were separated into drivers, and erase·half-word write·memory-mapped read operations were confirmed using application commands.

DEBUGGING

Separate the conditions under which long CDC transmission stops into two points

I checked the USB receiving endpoint and CDC transmitting status respectively.

  1. 01

    phenomenon reproduction

    We confirmed a condition where communication stops around 500 bytes when transmitting long data.

  2. 02

    Reactivate OUT Endpoint

    At the time of SOF, I checked the free ring buffer space and prepared the USB OUT endpoint again.

  3. 03

    TX BUSY data retention

    When CDC transmission is BUSY, it has been supplemented to maintain the transmission destination without consuming DMA RX data.

  4. 04

    Check the actual board

    I checked the terminal and board to see if long data continues to pass along the bridge flow after the fix.
