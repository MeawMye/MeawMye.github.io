PERSONAL PROJECT · STM32

PC 자원 정보를 STM32 LCD에
실시간 그래프로 시각화

PC에서 CPU·RAM·네트워크 사용량을 측정하고 UART로 전달해 STM32F729I-DISCO의 LCD에 최근 상태 변화를 표시했습니다.

LIVE DEMO

실제 보드 출력 결과

PC 자원 변화가 UART를 거쳐 LCD 그래프에 반영되는 과정을 확인할 수 있습니다.

현재 원본 영상은 HEVC 형식입니다. 공개 버전에서는 브라우저 호환성을 위해 H.264로 변환할 예정입니다.

01

문제 상황

전체 화면 작업 중에는 시스템 상태를 확인하기 위해 화면을 전환해야 했습니다. 별도 디스플레이에서 CPU, RAM, 네트워크 변화를 계속 확인할 수 있는 장치를 만들고자 했습니다.

02

담당 범위

Python 기반 PC 자원 측정과 포트 탐색, UART 송신부터 STM32 수신 인터럽트, 패킷 파싱, 이력 관리와 LCD 그래프 출력까지 전체 흐름을 구현했습니다.

03

해결 방법

  1. 측정psutil로 CPU·RAM 사용률과 네트워크 처리량 수집
  2. 전송필드와 경계를 정의한 텍스트 프레임을 UART로 송신
  3. 수신1바이트 인터럽트로 프레임을 조립하고 태스크에 완료 신호 전달
  4. 저장고정 크기 순환 버퍼에 최근 100개 샘플 유지
  5. 표시측정값을 LCD 좌표로 변환해 CPU·RAM·NET 그래프 출력

04

결과

약 1초기본 데이터 갱신 주기

100개고정 메모리 샘플 수

약 100초화면에서 확인 가능한 변화

PC 자원 변화가 실제 STM32 LCD에 반영되는 전체 경로를 확인했고, FreeRTOS 시작 이후에도 화면 출력이 유지되도록 보드 초기화 문제를 해결했습니다.

PROTOCOL

읽을 수 있는 텍스트 프레임

$CPU:35,RAM:62,NET:120#

$와 #로 바이트 스트림에서 프레임 경계를 식별했습니다. 사람이 읽기 쉬워 시리얼 디버깅이 간단하지만 체크섬과 엄격한 입력 범위 확인은 개선 과제로 남겼습니다.

DEBUGGING

LCD Bring-up 실패 원인을 단계적으로 분리

HardFault와 화면 미출력을 하나의 문제로 보지 않고 초기화 경로를 네 단계로 나누어 확인했습니다.

  1. 01

    Clock

    보드 예제와 PLL 설정을 비교해 SystemClock 불안정 가능성을 확인했습니다.

  2. 02

    Timebase

    TIM6 기반 HAL timebase 충돌을 확인하고 SysTick으로 분리했습니다.

  3. 03

    SDRAM

    외부 메모리 초기화 경로를 비교해 BSP_SDRAM_Init()을 사용했습니다.

  4. 04

    DSI

    패널 ON 명령과 초기화 순서를 보드 예제 흐름에 맞게 재배치했습니다.

확인 결과

LCD 초기화와 출력이 정상 동작했고 FreeRTOS 시작 이후에도 화면 갱신이 유지됐습니다.
