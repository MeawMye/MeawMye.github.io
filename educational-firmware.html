PERSONAL LEARNING PROJECT · STM32

주변장치 제어를 계층형 구조로 분리하고
통신 정지 원인을 코드 수준에서 해결

NUCLEO-F429ZI에서 USB CDC, USART6 RX DMA와 Internal Flash를 하나의 애플리케이션으로 연결했습니다. HAL 소스와 레퍼런스 매뉴얼을 함께 읽으며 GPIO·EXTI·UART의 하드웨어 동작도 추적했습니다.

Role
개인 프로젝트 · 전체 구현
Platform

C · STM32Cube HAL · USB CDC · DMA

LIVE DEMO

명령 실행과 통신 브리지 동작 확인

USB CDC 터미널에서 Flash erase·write·read 명령을 실행하고, 버튼으로 모드를 전환하며 USART6 DMA 수신과 CDC 브리지 동작을 확인했습니다.

프로젝트 PPT에 포함된 실제 보드 시연 자료이며 외부 서비스 없이 사이트 내부 파일로 재생됩니다.

01

문제 상황

주변장치별 예제는 동작했지만 기능이 늘수록 초기화와 제어 코드가 애플리케이션에 섞여 재사용과 원인 추적이 어려워졌습니다. USB CDC로 긴 데이터를 전달할 때 약 500바이트 부근에서 통신이 멈추는 현상도 발생했습니다.

02

담당 범위

BSP–Driver–Application 계층 설계, USB CDC와 UART 공통 인터페이스, USART6 RX DMA, Internal Flash 명령과 드라이버, 버튼 모드 전환 및 시연 흐름을 직접 구현했습니다.

03

해결 방법

  1. 분리보드 초기화, 장치 제어와 애플리케이션 로직의 책임 구분
  2. 연결USB CDC와 USART6를 공통 UART API로 묶고 RX DMA 순환 버퍼 적용
  3. 제어Flash erase·write·read 명령과 sector 정보를 드라이버로 구성
  4. 추적CDC 송수신 상태와 endpoint 재활성화 조건을 확인해 멈춤 원인 분리
  5. 비교HAL 구현을 GPIO·EXTI·UART 레지스터 동작과 대조

ARCHITECTURE

하드웨어 의존성과 애플리케이션 로직을 분리

호출 방향과 각 계층의 책임이 드러나도록 구성했습니다.

  1. USB CDC명령·데이터

UART BRIDGE

USART6 RX DMA 기반 전달

USART6 RX → DMA circular buffer
USB CDC ↔ Application ↔ USART6
PG14 TX · PG9 RX · 115200 bps

수신은 DMA 순환 버퍼, 송신은 polling 방식으로 구성했습니다. 브리지 모드는 버튼과 명령으로 전환합니다.

INTERNAL FLASH

Sector 11 테스트 명령

Base address  0x080E0000
Sector        11
Commands      erase / write / read

Sector 정보와 접근 코드를 드라이버로 분리하고 애플리케이션 명령으로 erase·half-word write·memory-mapped read 동작을 확인했습니다.

DEBUGGING

긴 CDC 전송이 멈추는 조건을 두 지점으로 분리

USB 수신 endpoint와 CDC 송신 상태를 각각 확인했습니다.

  1. 01

    현상 재현

    긴 데이터 전송 시 약 500바이트 부근에서 통신이 멈추는 조건을 확인했습니다.

  2. 02

    OUT Endpoint 재활성화

    SOF 시점에 ring buffer 여유 공간을 확인한 뒤 USB OUT endpoint를 다시 준비했습니다.

  3. 03

    TX BUSY 데이터 보존

    CDC 송신이 BUSY일 때 DMA RX 데이터를 소비하지 않고 전송 대상을 유지하도록 보완했습니다.

  4. 04

    실제 보드 확인

    수정 후 긴 데이터가 브리지 흐름을 따라 계속 전달되는지 터미널과 보드에서 확인했습니다.

REGISTER-LEVEL LEARNING

HAL 호출 뒤의 레지스터 동작을 추적

  • GPIOMode, output type, speed와 pull 설정 흐름 확인
  • EXTIGPIO 입력과 interrupt line, edge trigger 및 pending 처리 분석
  • UART초기화, baud rate와 DMA 요청이 동작으로 이어지는 과정 비교

RESULT & NEXT ITERATION

동작 예제를 넘어 유지보수 가능한 구조와 확인 기준을 구성

USB CDC, DMA UART와 Flash를 통합하고 통신 정지 원인을 상태 기반으로 분리해 수정했습니다.

01

계층형 구조

보드 초기화, 장치 제어와 애플리케이션 로직의 책임을 구분했습니다.

02

통합 동작 확인

CDC 명령, Flash 제어, 버튼 모드와 USART6 DMA 브리지를 실제 보드에서 확인했습니다.

03

다음 개선 항목

Blocking UART TX, 브리지 OFF 시 잔여 RX, linker의 Sector 11 포함, CubeMX 재생성 시 코드 보존과 odd-length write 지원을 후속 과제로 남겼습니다.
